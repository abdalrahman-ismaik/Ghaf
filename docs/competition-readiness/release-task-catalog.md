## Shared execution, awards and test keys

The current cloud lifecycle is Parent assignment → Child acceptance → start →
step markers → submission → Parent-written praise → separate recognition.
[SQL core](../../supabase/migrations/20260915000100_family_accounts.sql#L395)
enforces the selected family/Child, immutable accepted template, revision and
request receipt. It awards only after recognition: accepted acquisition amount,
or zero for recognition-only/maintenance. Help does not reduce that amount.
A recurrence label is not calendar scheduling.

In the table, **A** is a required Child action, **O** optional participation,
**C** conditional cooperation, and **D** adult responsibility or informational
guidance. Current UI/SQL require A=done and an explicit done/skip decision for
other rows. These are self-reported markers, not adult safety certification.

**R0** means recognition-only/not-applicable, null displayed award and zero
Seeds/permanent landscape/canopy. **F4/F6/F8** means fade-first acquisition with
4/6/8 Seeds; a separate Parent reauthenticated maintenance decision after the
routine threshold affects unaccepted/future assignments, not accepted awards or
past growth. **S4/S6** means one-time standard acquisition.
**H** = household; **CG** = Child/guardian privacy. Neither grants another
household task access. **G** adds one coarse Green canopy contribution on eligible
positive recognition and allows a Parent-created text memory. G does not mean
measured impact or automatically confer League/reward eligibility: the current
[separate growth eligibility rule](../../supabase/migrations/20260915000300_family_growth.sql#L78)
allows only canonical P0 for those credit paths, so **none of these 24 is
automatically a Challenge Leaf or Family Reward contribution**.

or its indoor equivalent, preacceptance smaller option, help facts and retry.
