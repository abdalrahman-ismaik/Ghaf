# Ghaf quality workflow

Use this for a requested review, stabilization slice, or rehearsal audit. Read the active
specification and `TEAM_OWNERSHIP.md`, record branch/commit and existing changes, and reserve
exact write boundaries before fixing anything. Do not activate a persistent persona or broaden
the assignment automatically.

Trace one concrete scenario from route to controller, service, immutable evidence, projection,
and reset. Prioritize reproducible failures by user harm and demo interruption: Parent/Child
authority, duplicate recognition, privacy leakage, accepted-help credit, permanent progress,
blocked task completion, fallback failure, then readability and polish. Keep a suspected issue
separate from a reproduced defect; give a trigger, expected/actual outcome, file location, and
smallest corrective boundary.

Run the checks proportional to the change in `AGENTS.md`. A behavior fix needs a regression that
would fail for the observed defect; cosmetic or documentation edits do not need implementation
mirror tests. Use existing scripts and isolated `tools/codex` tooling. Share test results between
agents when the source state is the same; rerun only when relevant files or unresolved failures
justify it. Do not run automatic dependency upgrades or force audit fixes.

For browser QA, use synthetic data and an isolated context. Capture the starting/reset state,
Arabic RTL and English LTR, compact width, and the exact flow under review. Record console
failures with their trigger. Browser passes do not pass native Back, keyboard, TalkBack, actual
permissions, process death, two-device delivery, or human cultural review.

Deliver a short prioritized issue list and an evidence matrix using `PASSED`, `FAILED`, `BLOCKED`,
or `NOT RUN`. Distinguish current results from historical checks. Report relevant dependency
advisories as triaged or untriaged, not proof of exploitability. Measure performance before and
after on comparable hardware if claiming a speed gain; omit invented percentages and scores.
Finish with owned files, checks, known gaps, and whether the slice is ready for integration.
