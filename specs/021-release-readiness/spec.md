# Feature 021 — Evidence-gated product release

Authority: the owner's 2026-09-14 execution request to complete the real Android
family product and every permitted backend/build/store publication step. This
extends Feature020 and supersedes older competition-only release exclusions for
this work; safety, privacy, approval, permanent growth and cultural rules remain.

The complete R01–R38/A01–A07 inventory and additional release obligations stay in
scope. A missing launch feature is a blocker, not a hidden completion or implicit
deferral. Explicit historical supersession stays documented. Supabase owns real
family/account data; new accounts contain no invented people/history/entitlements.
Demo is explicit and isolated; failure never returns mock success.

The release ledger is `docs/competition-readiness/release-readiness.md`. Separate
source, local tests, emulator, restricted hosted clients, physical devices and
store-distributed evidence. Public release requires the user's functional,
security, usability, quality, performance, policy, operations and publication gates.

Routine implementation, local/staging QA, compatible deployed changes and release
preparation are authorized. Public submission/publication is authorized only once
the actual identity/access, eligibility and gates are established. No purchases,
new prices, legal acceptance, identity documents, production-secret rotation or
real-data deletion are inferred. Production inspection is project-scoped and
metadata-first; destructive/adversarial/load tests belong in local/staging only.

Preserve package/signing identity, approved assets, original six-screen onboarding,
bilingual accessibility and working motion. Do not migrate frameworks or create
an alternate app to conceal integration gaps. Existing other-lane work is retained.

First implementation slice: the current internal Android workflow must run source
checks before producing artifacts. Provenance must include validated Android
version and every explicit demo/AI/candidate setting. An internal template-signed
APK remains internal and cannot pass store signing or public-release acceptance.

Gateway hardening slice: a configured remote AI gateway must reject operations
when its persistent replay binding is absent, before input processing, budget
reservation or provider invocation. Explicit in-memory test fixtures remain
available; there is no implicit production fallback. Keep live AI default-off
and retain authenticated operation isolation and unauthenticated MCP discovery.

Native permission slice: remove the Expo-template overlay permission
SYSTEM_ALERT_WINDOW, which no Ghaf user journey requires. Preserve supported
voice and secure storage behavior. The artifact validator must reject accidental
reintroduction and the next fresh native build must confirm the merged manifest.

Dependency hardening slice: update the transitive YAML parser within its existing
compatible version range to close the reported CPU-exhaustion advisory. Preserve
Expo/React Native versions and do not apply audit-suggested framework downgrades.
Record remaining findings by actual dependency path and runtime exposure.

Task safety/usability repair slice: the real task review and detail must expose
the catalog's adult-owned actions, second check, route constraint, indoor
alternative and aftercare in both languages. Rendering this information is not
proof that an adult performed it. Keep the missing authoritative prerequisite
review as an explicit blocker. A Child must be able to ask for help before
accepting an assigned task; that command preserves assignment, award and progress,
uses the existing restricted identity/revision/receipt rules and never implies
completion. Retry/adaptation lifecycle remains a separate unresolved requirement.
